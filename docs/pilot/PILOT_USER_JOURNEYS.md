# Pilot User Journeys

**Work order:** WO-ARGOS-039
**Method:** every step below was checked against the real, current `main` codebase (routes, guards, components actually present) — not assumed from the journey outline ARGOS provided. Where the outline's wording doesn't match what exists today, that's called out explicitly rather than silently substituted.

**Classification key:** `READY` (works today, verified in prior work orders or this one) · `MANUAL` (achievable but requires a workaround, a human doing something outside the UI, or tolerating a rough edge) · `MISSING` (no path exists at all today) · `NOT_REQUIRED` (out of this pilot's scope by design).

**What this means in practice:** the "pilot supervisor" role in this pilot is not a product feature — it's a person with `OWNER` credentials and comfort running a TypeScript seed script or a few `curl` commands, doing a one-time setup pass before the pilot starts. This is documented fully, and its acceptability for a pilot this size is judged in `PILOT_GO_NO_GO.md`, not assumed here.
