## Cross-cutting observation

The `DemoBanner` (dismissible "Entorno piloto · Datos de demostración" banner) and `DemoNotice` (inline badge) components are correctly implemented and consistently used across every mock-data screen — the product is honest, in its own UI, about which screens are demo. This does not change any screen's actual completion state, but it means the risk of a stakeholder mistaking mock data for real data is already mitigated in the UI itself.

## Charging infrastructure navigation (WO-ARGOS-005)

ARGOS ruled against building org-wide "list all X" endpoints for `ChargingStation`/`Evse`/`Connector` — the canonical navigation is strictly Site-scoped (`Organization → Site → ChargingStation → EVSE → Connector`), never a flat cross-org list. As a result:

- **Canonical infrastructure entry point:** `/sites` → a Site's detail page → its "Infraestructura" tab → drill into a `ChargingStation` → its EVSEs → their Connectors. Every real, connected charging screen hangs off this one path.
- **`/stations` redirects to `/sites`** (its closest real equivalent already existed and was production-ready — no duplicate screen was built).
- **`/chargers` and `/connectors` are now Site-selection gateways**, not lists — they explain the Site-first requirement and link into the canonical path above. They deliberately do not attempt to reconstruct a flat list client-side (no N+1 fan-out across every Site's stations/EVSEs).
- **`/chargers/[id]` redirects to `/chargers`** — a mock charger id from the old fixture data has no real EVSE to map to, so it falls back to the gateway rather than 404ing or dead-ending.
- None of the retired routes render mock `Station`/`Charger`/`Connector` records anymore. The underlying fixture files (`src/data/{stations,chargers,connectors}.ts`) are preserved unchanged — they are simply no longer reachable as live-looking screens (see [CAP-002 Charging Terminology Mapping](../domain/CAP-002_CHARGING_TERMINOLOGY_MAPPING.md) for the full rationale).
