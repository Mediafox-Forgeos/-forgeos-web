## Dependencies

Sessions, Tariffs, Alerts, Reporting, Billing, and Notifications all ultimately depend on the Charging Core (Station/EVSE/Connector) existing, which now has both a CRUD backend (CAP-002) and a connected, Site-scoped management UI (WO-ARGOS-004). CAP-003 (WO-ARGOS-007) added a first OCPP vertical, but none of Sessions/Tariffs/Alerts/Reporting/Billing/Notifications are unblocked yet — they need `Authorize`/`StartTransaction`/`StopTransaction` handling and a real `ChargingSession` model, neither of which this vertical implemented. See the [Dependency Map](./MOVOS_DEPENDENCY_MAP_v1.0.md) for the full graph.

**Note on "Frontend: Yes":** this means the real `ChargingStation`/`Evse`/`Connector` records are viewable and editable through `apps/movos-web`, scoped per-Site (`/sites/[id]/charging-stations/...`). As of WO-ARGOS-005, the formerly-mock `/stations`, `/chargers`, `/connectors` pages were also retired: `/stations` redirects to `/sites`, and `/chargers`/`/connectors` are real Site-selection gateways into the same Site-scoped flow — none of the three renders mock infrastructure data anymore. No org-wide list-all endpoint was built to give them a flat list of their own; that remains a deliberate, ARGOS-confirmed scope decision, not a gap. See [Screen Inventory](./MOVOS_SCREEN_INVENTORY_v1.0.md).

## Technical risk concentration

OCPP was the one item with no architectural precedent anywhere else in the codebase to reuse — it required a stateful/persistent-connection transport (WebSocket), while everything shipped before CAP-003 was HTTP request/response. CAP-003 (WO-ARGOS-007) established that precedent (protocol adapter pattern, normalized event vocabulary, in-memory connection registry) and proved it against a first vertical, `SIMULATOR_VALIDATED` only — no physical hardware. The remaining risk concentration shifts to what CAP-003 deliberately did not attempt: `Authorize`/`StartTransaction`/`StopTransaction` and real `ChargingSession` continuity across reconnects (a real-time, stateful problem with no precedent yet either), and OCPP 2.0.1 functional support (currently a boundary-only stub that explicitly rejects every message).
