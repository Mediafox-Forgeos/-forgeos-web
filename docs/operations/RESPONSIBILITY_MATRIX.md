# Responsibility Matrix

**Work order:** WO-ARGOS-034 (Operational Actors & Responsibility Model)
**Status:** DOMAIN DISCOVERY. No code, frontend, backend, migration, or API change.
**Mission:** for each real operational event, who detects it, who acknowledges it, who assigns it, who executes it, who supervises it, and who closes it — using the actors defined in [OPERATIONAL_ACTORS.md](./OPERATIONAL_ACTORS.md).

## How to read "detects"

The most important finding in this document shows up in the first column, not the last: **for two of the five events below, MOVOS itself is the detector, not a human.** That's not a simplification — it's a real, load-bearing fact about this product that the mission's own framing (which lists only human actor examples) doesn't assume. Naming where the detector is software, not a person, is exactly the kind of honest distinction this discovery sprint exists to surface.

## The matrix

### 1. Connectivity loss

| Step         | Actor                                        | Real mechanism                                                                                                                                                                                                           |
| ------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Detects      | **MOVOS** (`ConnectivityCoordinatorService`) | Automated — no human notices this first, per CAP-005's own design                                                                                                                                                        |
| Acknowledges | Network Operator                             | Sees it on Command Center's health verdict or Network's connectivity badge ([KYLUM_CONSOLE_VISUAL_GUIDE.md](../product/KYLUM_CONSOLE_VISUAL_GUIDE.md))                                                                   |
| Assigns      | Dispatcher (same account as Operator)        | `WorkOrder.assign`, once [WORK_ORDER_AUTOMATIONS.md](./WORK_ORDER_AUTOMATIONS.md) Rule 1 has created the order automatically after 15 minutes                                                                            |
| Executes     | Field Technician                             | Off-product entirely — a phone dispatch, physical inspection                                                                                                                                                             |
| Supervises   | Operations Manager                           | Only if the SLA clock ([ESCALATION_MODEL.md](./ESCALATION_MODEL.md)) is at risk — otherwise passive                                                                                                                      |
| Closes       | Network Operator                             | `WorkOrder.resolve`, based on the technician's phone report — **never the technician directly**, per [OPERATIONAL_ACTORS.md](./OPERATIONAL_ACTORS.md)'s structural finding that Field Technicians have no product access |

### 2. Charger/connector offline (a detected fault, not a raw connectivity loss)

| Step         | Actor                               | Real mechanism                                                                                                                                                                           |
| ------------ | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Detects      | **MOVOS** (`RecommendationService`) | `IDLE_CONNECTOR`, `ENERGY_ANOMALY`, or another of the five real detectors ([OPERATIONAL_INTELLIGENCE_TECHNICAL_NOTES.md](../implementation/OPERATIONAL_INTELLIGENCE_TECHNICAL_NOTES.md)) |
| Acknowledges | Network Operator                    | `Action.acknowledge`, on the Operations screen                                                                                                                                           |

| Supervises   | Operations Manager                  | For `HIGH`/`CRITICAL` priority only                                                                                                                                                      |

### 3. Maintenance request (scheduled/preventive)

| Step         | Actor                                   | Real mechanism                                                                                                                                                                                                                                                                   |
| ------------ | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Detects      | **Nobody, automatically — a real gap.** | No scheduling or preventive-maintenance trigger exists anywhere in MOVOS today. A maintenance request originates entirely from a human noticing something (an Operations Manager reviewing a chronic-station pattern, or a technician mentioning wear during an unrelated visit) |
| Acknowledges | Operations Manager                      | Typically the one who decided the maintenance was worth scheduling in the first place                                                                                                                                                                                            |
| Assigns      | Dispatcher                              | `WorkOrder.assign`, `source: MAINTENANCE`                                                                                                                                                                                                                                        |
| Executes     | Field Technician or External Contractor | Interchangeable in this version, per [OPERATIONAL_ACTORS.md](./OPERATIONAL_ACTORS.md)'s open contractor-modeling question                                                                                                                                                        |
| Supervises   | Operations Manager                      | Directly — this is the one event type this actor is most likely to have initiated themselves                                                                                                                                                                                     |
| Closes       | Network Operator                        | Same mechanism as every other `WorkOrder`                                                                                                                                                                                                                                        |

### 4. Customer complaint

| Step         | Actor                                                                                                  | Real mechanism                                                                                                                                                                                                                                                                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Detects      | **Customer Support**                                                                                   | The first row in this matrix where the detector is a named human actor with a real `MemberRole` (`SUPPORT`), not software — a driver calls or messages in                                                                                                                                                                                                     |
| Acknowledges | Customer Support                                                                                       | Confirms the report is real and gathers what session/station it relates to — a genuinely manual, unassisted lookup today, per [PRODUCT_GAPS.md](../product/PRODUCT_GAPS.md) gap #4 (no driver-to-session lookup exists)                                                                                                                                       |
| Assigns      | Dispatcher                                                                                             | `WorkOrder.assign`, `source: CUSTOMER_REPORT`                                                                                                                                                                                                                                                                                                                 |
| Executes     | Field Technician (if physical) or Customer Support directly (if not — e.g., a credential/access issue) | Branches depending on the complaint's real nature                                                                                                                                                                                                                                                                                                             |
| Supervises   | Operations Manager                                                                                     |                                                                                                                                                                                                                                                                                                                                                               |
| Closes       | **Customer Support, not the Network Operator**                                                         | This is the one event type in this matrix where closing the `WorkOrder` (the technical fix) and closing the loop with the actual customer are two different facts — MOVOS can represent the first, and has no channel at all for the second, a real, distinct gap beyond what [PRODUCT_GAPS.md](../product/PRODUCT_GAPS.md) already named for driver contacts |

This row is included deliberately, not as a formality — a responsibility matrix that skipped the one event type MOVOS genuinely cannot support yet would be quietly overstating the product's real coverage. The honest entry is "not yet possible," not a best-effort guess at who _would_ own it.

## What this matrix found, read across all five rows

Two structurally different kinds of "detects" exist side by side in this product: automated (connectivity loss, recommendations) and human-reported (customer complaints, maintenance needs an Operations Manager notices). MOVOS is mature on the first kind and has no real channel for the second — every human-detected event in this matrix runs into the same underlying gap, a missing structured intake surface for anything that doesn't originate from the fleet's own telemetry. **"Closes" is the Network Operator in four of five rows, and never the Field Technician in any of them** — the single clearest, most consistent finding in this document, and the one [WORKORDER_READINESS.md](./WORKORDER_READINESS.md) leans on hardest when assessing whether `WorkOrder`'s design already matches reality.
